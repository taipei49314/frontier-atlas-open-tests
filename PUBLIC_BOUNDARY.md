# Public boundary

Safe-to-publish candidates include protocol documentation, schemas, training
inputs without hidden keys, deterministic canonicalization/hash verification,
aggregate denominators, release hashes, and known limitations.

Never publish private qualification answer keys, contributor assignments,
salts before reveal, gold/adjudication, sealed cases or labels, provider keys,
production prompts, routing policy, raw user data, or security-sensitive
incident details.

GitHub signatures establish account provenance, not unique-human identity.
Sybil resistance and gold authority remain private governance concerns.
